# 4and.one audit — 13 October 2026

## Executive assessment

The reported Finals fault was real: its gain-routed element explicitly disabled pitch preservation. Timing also used recording seconds and different limits per dance. The fix uses pitch-preserving native tempo control, 105 elapsed playback seconds including a three-second fade, the existing 15-second silent MP3, then the next dance. Pausing freezes the music/rest slot. Tempo changes during rest affect the next dance only. The last dance ends the program without an extra rest.

Short recordings repeat to fill the full 105-second slot at the selected tempo. This is intentional: the catalogue contains recordings shorter than the required slot. Full musical-quality acceptance on physical iOS and Android devices remains necessary.

Grade after this change: **B for Finals and server authorization, C for overall product completeness**. Automated checks are not a claim that every external integration or mobile background scenario is certified.

## Validation

- **60 passing tests** across six suites. Unit/integration tests cover complete 105 → 15 → 105 Finals flows, duplicate tracks, speed changes, rest pause/resume, clock wrap, pitch flags, iOS gain-path scheduling/cleanup, PayPal verification/cancellation, ownership filters, Telegram signatures, media keys and HTML injection.
- Twenty actual protected route/method exports reject anonymous requests before mutations, including Telegram, AdSense, upload, albums, contact administration and cron.
- Chromium audio measurement: a generated 440 Hz tone remained approximately 440.085 Hz at 50%, 80%, 100%, 120% and 150% tempo. This is a frequency regression test, not a subjective music-quality score.
- Chromium layout smoke test: 19 routes × 360/430/1440 widths, no horizontal document overflow or uncaught page errors. Admin data and external actions used controlled responses; public catalogue requests were unavailable in this browser environment. Populated-table and full live integration acceptance are therefore still required.
- Supabase transactional regression checked successful promo, repeat rejection, usage cap, referral repeat rejection and one inviter reward. All synthetic rows were rolled back; zero audit users remained.
- Production `npm run build` passes on Next.js 16.4.0; standalone test TypeScript also passes.
- Dependency audit (`npm audit --omit=dev`): 24 findings (2 critical) before updates, 9 high / 0 critical after. Remaining chains are next-pwa/workbox build tooling; the unused onnxruntime-web dependency was removed.
- Application TypeScript remains checked by production build. Test TypeScript is checked separately using tsconfig.test.json to avoid loading the entire test runner into Next's build worker.
- Source lint comparison before dependency upgrade: 190 errors / 270 warnings at the original commit, 188 errors / 274 warnings after this change. Final full-repository lint after the Next/eslint-config upgrade reports 238 errors / 274 warnings. Repository-wide lint is not clean. No blanket lint suppression was added.

Machine-readable browser and pitch evidence is adjacent to this report. `scripts/audit/pitch.cjs` can be run with Playwright Chromium installed (`PLAYWRIGHT_MODULE` can specify an existing installation).

## Remaining risks and acceptance work

1. Physical iPhone/Safari/PWA and Android lock-screen tests: slow a real song, pause at 1:43, resume, lock the screen through the silent interval, interrupt with a call, and play a full five-/ten-dance program. Browser simulation cannot establish OS background behavior or subjective audio quality.
2. Real PayPal sandbox checkout, renewal, cancellation and refund acceptance. No charge was made and no real subscription was cancelled in this audit. There is no dedicated PayPal webhook route in this repository; renewal remains a server lookup when premium status is read. Refund/suspension handling needs a verified webhook design.
3. Real R2 upload, Telegram delivery/check-status, AdSense connection and email delivery were not exercised with production side effects. Telegram tests did not contact users. Historical exposure of R2 OAuth credentials was not determined; inspect access logs and rotate credentials if exposure is confirmed. Secrets were not retrieved during this audit.
4. Legacy predictable-password Supabase Auth accounts should have credentials and refresh sessions retired. RLS lockdown removes their access to private app tables, but it does not change Auth credentials themselves.
5. Distributed rate limiting is still needed for public contact/analytics/login endpoints. Analytics events remain client-reported and cannot be treated as fraud-resistant financial evidence.
6. Existing lint debt remains; PWA tooling dependency advisories must be tracked separately. No forced downgrade of next-pwa was applied.
7. AI processing and several settings controls have no backend implementation. They are explicitly unavailable rather than presented as completed features.
8. Collection reorder consists of multiple owned updates; an interrupted save can be partial. The UI reports failure and reloads the stored order. An atomic reorder RPC would improve this further.

## Rollout

Apply additive ownership/reward migrations, deploy the application, confirm public catalogue and authenticated gateways, then apply `secure_catalog_and_private_data`. Do not roll back to the old browser-direct private-data client after access lockdown. No user catalogue or collection data is deleted by these migrations.
